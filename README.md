# ⭐ GRIZZ STARS BOT

Telegram-бот магазина: **аккаунты** (покупка на Lolz Market), **Stars / Premium** (Fragment), **Голда** (заявки), **TON** (только покупка как товар; TON-пополнение баланса остаётся отдельным способом оплаты).
Всё в **гривнах (₴)**, интерфейс на русском. Премиум-эмодзи по гайду https://emoji.wivvi.net.

- Поддержка: @mango_user · Канал: https://t.me/mangostarss (**обязательная подписка**) · Чат: https://t.me/mango_markett
- ⚠️ Бот должен быть **администратором канала @mangostarss**, иначе проверка подписки не работает.
- Для отзывов бот также должен быть **администратором @repmango** с правом публикации. Укажите `REVIEWS_CHANNEL` и `REVIEWS_CHANNEL_URL` в `.env`.

## Запуск
```bash
pip install -U -r requirements.txt      # aiogram обновите: нужен Bot API 9.4+ (иконки на кнопках)
cp .env.example .env                    # заполнить
python main.py
```
Supabase: SQL Editor → вставить **`supabase_schema.sql`** целиком → Run (скрипт безопасно запускать повторно; в нём есть таблицы отзывов и тикетов поддержки).
В `.env` нужен ключ **service_role**.

## Разделы бота
| Раздел | Как работает |
|---|---|
| `/start` | Приветствие Mango Shop, основные возможности и ссылка на канал отзывов |
| ✈️ Telegram аккаунты | Покупка на Lolz Market. Цена страны — в ₴, задаётся в админке. Сравнивается с ценой Lolz (₽) по курсу из «Себестоимость → Курс Lolz» |
| ⭐ Stars / 💎 Premium | Оплата с баланса, доставка через Fragment (как раньше) |

**Имя отправителя Stars/Premium:** Stars и Premium с Fragment всегда отправляются **анонимно** (`show_sender=0`) — получатель не видит ваш аккаунт. Кошелёк, подключённый в Fragment, должен соответствовать `TON_MNEMONIC`.
| 🥇 Голда | Купить / Продать → сумма → комментарий (или «Пропустить») → проверка → «Отправить заявку» → **«Заявка №N»** уходит всем админам |
| 💠 Купить TON | Цена = курс + наценка продажи. Клиент выбирает количество, вводит свой адрес, платит с баланса — бот отправляет TON со своего кошелька |
| Пополнить | 💳 Перевод на карту · 🪙 Crypto Bot (счёт в UAH) · 💠 TON |

### Голда — заявки
Админам приходит карточка: тип, сумма, комментарий, клиент. Кнопки: **Написать клиенту** (по @username), **Ответить в боте** (ответ приходит клиенту
с кнопкой «Ответить» — получается переписка по заявке), **Взять в работу / Выполнено / Отклонить** (клиент получает уведомление о статусе).
Заявка автоматически приходит администраторам отдельной карточкой; управление статусом доступно прямо в этой карточке.

### Пополнение картой
**С Monobank API (рекомендуется)** — задайте `MONOBANK_API_TOKEN` (застосунок Monobank → «Ще» → «Інше» → Monobank Open API). Карта, реквизиты которой видит клиент
(«Реквизиты карты» в админке или `CARD_*` в `.env`), **должна быть с этого токена**.
1. Клиент вводит сумму → бот даёт **уникальную сумму с копейками** (например `100.37 ₴`): по ней платёж опознаётся даже при одновременных оплатах. На баланс идёт ровно переведённое.
2. Клиент переводит и нажимает **«Проверить оплату»** → бот пишет «⏳ Идёт проверка платежа, подождите минуту…», сверяет выписку Monobank и:
   нашёл — зачисляет и пишет «Платёж найден», не нашёл за минуту — «❌ Платёж не найден…» (с подсказкой повторить).
3. Если клиент оплатил и не нажал кнопку — раз в минуту бот сам ищет оплаты по открытым заявкам. На оплату даётся `MONOBANK_PAYMENT_TTL_MIN` минут (30).
4. Транзакция Monobank занимается в БД (`used_mono_tx`, PK = id) — одну оплату нельзя зачесть дважды. Лимит Monobank 1 запрос выписки в минуту на токен — бот ставит проверки в общую очередь, поэтому ответ приходит до ~минуты.

**Без токена** — запасной режим: клиент жмёт «Я оплатил», шлёт скрин/PDF чека, админ подтверждает кнопкой («Подтвердить / Отклонить / Другая сумма»). Один файл чека дважды не принимается.

### Пополнение через TON
Клиент отправляет **любую сумму TON** на адрес приёма и пишет в комментарии **свой ID** (бот показывает его). Бот сам каждые ~30 сек ищет переводы
и зачисляет `TON × курс`; кнопка «Проверить баланс» делает проверку сразу, «Отменить» закрывает экран.
- Адрес приёма и курс: админка → «Настройки TON». Если адрес не задан, а `TON_MNEMONIC` есть — принимает на кошелёк бота.

### Курс TON и наценки
Админка → «Настройки TON»:
- **Источник курса** — кнопка-переключатель: **Сайт** (CoinGecko, TON→UAH, обновляется раз в минуту) или **Свой** (число из «Свой курс»).
- **Покупка у клиента (−)**: сколько ₴ вычитается из курса. Это вычет из курса при TON-пополнении баланса.
- **Продажа клиенту (+)**: сколько ₴ добавляется к курсу при «Купить TON».
- Пример: курс 130, покупка 4, продажа 5 → при пополнении клиент получает 126 ₴ за 1 TON, а при покупке TON платит 135 ₴ за 1 TON. Для «Покупка у клиента» значения `3` и `-3` оба означают вычесть 3 ₴. Заголовок раздела показывает текущие базу, выкуп, продажу и спред.
- Если курс сайта не обновлялся дольше 15 минут (сбой источника), TON-операции ставятся на паузу, а админам приходит предупреждение — можно переключить на «Свой».
- **Защита:** каждая транзакция записывается в БД по хэшу (`ton_deposits`, PK = tx_hash) **до** зачисления — повторно не зачтётся; старая история адреса
  (до момента настройки) игнорируется; перевод без ID / с несуществующим ID не зачисляется — админам уходит уведомление и запись в «TON без привязки».
- Курс фиксируется в момент зачисления.

## Язык бота (русский / украинский)
При первом `/start` новый пользователь выбирает язык — **до проверки подписки на канал**; после выбора бот просит подписаться на @mangostarss, затем регистрирует и открывает меню.
Реферальная ссылка при этом не теряется. Сменить язык можно в «Профиль → Язык / Мова». Язык хранится в `users.lang`.
Как устроено (`i18n.py`, `i18n_uk.py`): код пишет и понимает русский; для украинских пользователей исходящие тексты и кнопки переводятся по таблице, а нажатые украинские кнопки
превращаются в русские перед обработкой. Админ-панель остаётся на русском. Новый текст в коде без пары в `i18n_uk.py` просто останется русским — добавьте пару `'русский фрагмент': 'український'`.

## Админ-панель
Главная админ-панель содержит только частые действия: **Статистика**, **NFT каталог**, **Пользователь**, **Начислить баланс**, **Промокод** и **Рассылка**.
Редкие инструменты разнесены по подразделам: **Товары и цены** (аккаунты, Stars/Premium), **Платежи** (TON, карта, непривязанные TON-переводы), **Журнал и сервис** (последние покупки/пополнения, балансы поставщиков и себестоимость).
Ручное создание отзывов из админки отключено: отзывы публикуются через обычный клиентский сценарий после завершённой покупки.

**Уведомления админам:** каждое пополнение баланса (кто, сколько, чем), каждая продажа (аккаунт/Stars/Premium/TON с прибылью), чеки на проверку, сбои и неясные заказы.

### Как считается прибыль
`чистая = цена клиента − себестоимость − реферальный бонус`. Себестоимость аккаунта — реальная цена Lolz × курс ₽→₴; Stars / Premium / TON — значения из
админки «Себестоимость» (не заданы → 0). Журнал — таблица `sales`.

## Деньги и защита
- Баланс списывается до выдачи; явный отказ → автовозврат; неясный итог (мог уйти аккаунт/TON) → возврата нет, админу 🚨-алерт.
- Все зачисления идут через одну функцию (`billing.credit_topup`) с «claim»-защитой от двойного зачисления.
- Покупка TON: только на валидный TON-адрес; суммы в пределах лимитов из админки.

### Отзывы и поддержка
После успешной покупки аккаунта, Stars/Premium или TON появляется кнопка **«Оставить отзыв»**. Клиент выбирает 1–5 звёзд и может добавить комментарий; отзыв публикуется в `REVIEWS_CHANNEL` с номером, ником без `@`, товаром, суммой и датой. Под каждым отзывом — только одна кнопка **«Перейти в бота»**. Один отзыв на одну покупку.

Раздел **«Поддержка»** позволяет создать тикет и вести переписку в боте. Новые сообщения отправляются администраторам из `ADMIN_IDS`; ответ админа приходит клиенту в этот же чат. Таблицы отзывов и тикетов создаются из `supabase_schema.sql`.

## Что нового (отзывы, эмодзи, скорость, перевод)

**Отзывы**
- Нумерация общая и начинается с `REVIEW_START_NUMBER` (979): «Відгук #979», «#980» … (по реальным завершённым покупкам).
- Звёзды в постах — премиум-эмодзи. Свою звезду из другого пака задайте `REVIEW_STAR_EMOJI_ID`; ID пака можно получить командой админа
  `/emojiids https://t.me/addemoji/НАЗВАНИЕ_ПАКА` (или `/emojiids` вместе с премиум-эмодзи в сообщении).
- Кастомные эмодзи-иконки на кнопках требуют Telegram Bot API 9.4+ и Premium у владельца бота (или приобретённых username на Fragment). Telegram не делает кликабельными хештеги только из цифр: `#979` виден как текст. Нужен кликабельный — `REVIEW_TAG_PREFIX=r` → `#r979`.
- Один раз выполните в Supabase: `ALTER TABLE bot_reviews ADD COLUMN IF NOT EXISTS photo_id TEXT DEFAULT '';` (без этого отзывы работают, но фото не сохраняется в БД).

**Перевод RU → UK**: недостающие тексты — в `i18n_uk_extra.py`; новые строки в коде ищите командой `python check_i18n.py`.

**Скорость**: кэш file_id баннеров (картинки больше не заливаются каждый раз), кэш настроек и бан-проверки, кэш переводов,
фоновые проверки платежей не блокируют бота, uvloop (по возможности).

## NFT-подарки (ручная выдача + канал товаров)

- Админ: «NFT каталог» → «Добавить NFT» → ссылка `t.me/nft/…`, эмодзи для кнопки подарка, цена и себестоимость. Выбранный Premium Custom Emoji используется как иконка кнопки в личном каталоге; обычный Unicode-эмодзи показывается в тексте кнопки. Товар автоматически публикуется в `NFT_CHANNEL` с ценой, ссылкой на NFT и кнопкой «Купить».
- Канал по умолчанию — `@mangostarss`. Его можно переопределить через `NFT_CHANNEL` в `.env`. Бот должен быть администратором канала с правом публикации и редактирования сообщений. Для старых товаров используйте «Опубликовать товары в канал».
- В проект добавлен баннер-заглушка `images/nft.jpg`: он показывается в NFT-разделе бота и используется в новых публикациях NFT, пока отдельного изображения самого подарка нет.
- Чтобы оформить пост о продаже, опубликуйте фото в канале магазина с подписью ровно `s`. Бот оставит фото, заменит подпись на **«💞 Продано! / Sold!»** и добавит большую акцентную кнопку **«Бот Каталог»**, а под ней **«Звёзды»** и **«Отзывы»**. «Звёзды» открывает сразу экран покупки Stars в боте; «Отзывы» ведёт в `REVIEWS_CHANNEL_URL`. Бот должен получать `channel_post` updates и иметь разрешение редактировать сообщения.
- Кнопки поста ведут сразу в нужный раздел через `/start`-ссылку; если товар уже снят или зарезервирован, статус всё равно проверяется в базе.
- Кнопка «Купить» открывает в боте карточку именно выбранного NFT, а не отзывы или общий каталог. Если товар уже продан, зарезервирован или снят, бот покажет актуальный статус; кнопка в канальном посте убирается.
- После подтверждения оплаты товар атомарно резервируется, сумма списывается с баланса, а всем админам приходит заявка с данными клиента и кнопками **«Выполнено»** и **«Отказать / вернуть деньги»**. Выдайте NFT вручную, после чего нажмите «Выполнено»: заказ фиксируется в статистике, а клиенту приходит уведомление. При отказе сумма возвращается на баланс и товар снова появляется в продаже.
- Админ-панель NFT содержит очередь заявок, каталог, управление ценой и видимостью, удаление и публикацию товаров. Заявки нельзя просто снять с резерва: для отказа используйте кнопку возврата, чтобы клиент не потерял деньги.
- Подключение Telegram Business / `NFT_WAREHOUSE_IDS` необязательно и используется только для дополнительной сверки склада. Оно не выдаёт товар автоматически.
- Выполните в Supabase блок «15. NFT-ПОДАРКИ» из `supabase_schema.sql` (один раз), если NFT-таблица ещё не создана.

### Автоматическое первое развёртывание TON-кошелька

Если кошелёк `v3r2`/`v4r2` уже пополнен, но TON Center показывает `account_state=uninitialized` и `seqno=0`, бот не просит повторно переводить TON. При первой реальной оплате `tonsdk` добавляет `StateInit` к подписанному внешнему сообщению и тем самым развёртывает кошелёк одновременно с выполнением платежа. Отдельный пустой активационный перевод не нужен. Бот проверяет `account_state`, `seqno` и баланс до отправки, после broadcast ждёт перехода в `active` и увеличения `seqno`. Для `frozen`, неправильного адреса или недостаточного баланса отправка блокируется. Если итог транзакции неясен, заказ остаётся на проверке — автоматический повтор/возврат не выполняется, чтобы не допустить двойного списания.

В админке → «Fragment / TON» отображаются адрес, баланс, `account_state` и `seqno`. Диагностика Fragment проверяет доступность страницы/API и больше не делает ложный тестовый поиск по жёстко заданному `durov`; авторизация cookies и существование получателя проверяются на реальном username перед заказом.


## Языки и баннеры
- Языки: русский, украинский, английский. При первом запуске: **язык → подписка на канал → бот**. Сменить язык: «Профиль → Язык / Мова / Language».
- Переводы: `i18n_uk.py`, `i18n_uk_extra.py`, `i18n_en.py` (формат «русский фрагмент → перевод»). Непереведённый текст остаётся русским.
- Обязательная подписка: `REQUIRED_CHANNEL` в `.env`. Пусто — проверка полностью отключена. Кнопки: «Подписаться» (primary) и «Проверить подписку» (success, зелёная).

Главное меню = `home`. Экран выбора языка: `lang.jpg` (необязательно). Сейчас `home_*` и `sub_*` — заглушки.
- Рассылка (админка): работает форматирование, цитаты, спойлеры, премиум-эмодзи, фото/видео/GIF/файл с подписью; обычные эмодзи автоматически становятся премиум; текст рассылки не переводится.
